# Compact degree-5 Macaulay certificate audit

## Verdict

There is a rigorous certificate much smaller than a rank certificate for the
full `4,496,388`-dimensional degree-5 target:

```text
q_i^5 e_j in N,       0 <= i < 37,  0 <= j < 6,                 (222 checks)
```

where `N` is the submodule of `S^6`, `S=F_89[q0,...,q36]`, generated by the
10,767 cubic contractions.  These memberships imply
`(q0^5,...,q36^5)S^6 subset N`, so `S^6/N` has finite length and its
projective support is empty.  They do **not** require surjectivity of the full
degree-5 Macaulay map.

An equally valid and potentially easier certificate is a common-order initial
module cover: exhibit homogeneous `g_ij in N` with

```text
LT_prec(g_ij) = q_i^a(i,j) e_j,       a(i,j) <= 5
```

for all 222 pairs and for one fixed global multiplicative module order
`prec`.  Then every component ideal of `in_prec(N)` is irrelevant-primary,
so `S^6/in_prec(N)` and hence `S^6/N` have finite length.  No complete
Groebner basis is needed to verify such a packet.

This audit did **not** find a genuinely feasible low-memory discovery
computation with the current data.  The 222-row output format is
compact, but generic lifts and every direct unstructured solver remain too
large.  The viable next implementation needs either an exact representation
block decomposition or a custom binary, degree-truncated module F4/F5 engine
that retains a shared row-operation DAG.  A raw Singular/Macaulay2 job, a raw
degree-5 matrix, and the direct degree-3-syzygy matrix should not be launched.

## Exact dimensions and replay

Run the lightweight audit from the repository root:

```text
/opt/homebrew/bin/python3 \
  P25_LANDING_SUPPORT/parallel/stageb_cas/audit_compact_degree5.py
```

It writes `compact_degree5_plan.json` and binds the sealed relation tensor

```text
relation_matrix.npz sha256
6aeeeb0b1bdc81dafec9872f7543468f426336ccc3ed11087bfa56e9dddaa4fb
```

The relevant dimensions are:

| degree | source `10767 dim S_(d-3)` | target `6 dim S_d` |
|---:|---:|---:|
| 3 | 10,767 | 54,834 |
| 4 | 398,379 | 548,340 |
| 5 | 7,569,201 | 4,496,388 |

Thus full degree-5 surjectivity is dimensionally possible, but its dense
matrix has `34,034,064,545,988` entries (about 31.7 TiB even at one byte per
entry).  Testing 222 distinguished targets changes the desired output, not
the size of an unstructured elimination.

The already natural binary objects are much smaller:

```text
full K1 basis:       274,881,510 uint8 bytes  (262.1 MiB)
full cubic module:   590,397,678 uint8 bytes  (563.0 MiB)
```

They are suitable producer inputs, but not evidence that degree-5 elimination
will remain near those sizes.

## What a verifier should accept

The preferred order-free packet stores, for each `(i,j)`, coefficients
`h_ijk in S_2` satisfying

```text
sum_k h_ijk f_k = q_i^5 e_j,
```

where the `f_k` are the 10,767 cubic contractions.  An independent streaming
verifier must:

1. reconstruct every referenced degree-one syzygy `C_k(q)` and check
   `C_k(q)M2(q)=0` against the sealed tensor;
2. reconstruct `f_k=C_k(q)M1(q)` exactly over `F_89`;
3. accumulate each displayed lift and compare every degree-5 coefficient with
   the single claimed target coefficient;
4. verify that all 222 `(variable,component)` pairs occur.

For an initial-module packet, step 3 instead reconstructs `g_ij`; the verifier
then computes its leading term under the packet's **single declared order**
and checks that it is a pure power in the stated component.  The proof uses
only the selected elements and their lifts.  It does not trust a truncated
CAS declaration that its output is a complete standard basis.

A sparse triangular certificate is valid only in this stronger sense: each
selected row must have zero coefficient in every term larger than its claimed
pure-power pivot, and its lift to the input module must be checked.  A bare
`222 x 222` nonzero minor only proves independence; it does not prove the
pure powers lie in the row span and is not an emptiness certificate.

The count 222 is the natural minimum for a homogeneous pure-leading-term
cover.  A proper monomial ideal in one component is irrelevant-primary only
if it contains a pure power of each of the 37 variables; a monomial generator
dividing a pure power must itself be a pure power in that variable.  This is
37 leading generators per component and six components.  Exact group orbits
could compress how the 222 identities are stored, but only after explicit
action matrices and equivariance checks are supplied; none is currently
sealed for this 37-dimensional `q` space.

## Monomial-order audit

All leading terms must be computed under one common order.  Combining covers
found using different orders is invalid.  For example, `(x+y)` has leading
term `x` for `x>y` and leading term `y` for `y>x`; combining the two would
falsely claim the irrelevant ideal although `Proj k[x,y]/(x+y)` is nonempty.

The installed Singular 4.4.1 manual distinguishes:

```text
(dp,C) or (dp,c): monomials first, then module components
(C,dp) or (c,dp): components first, then monomials
```

For discovery, a fixed term-over-position order such as `(dp,C)` is the
appropriate default: it lets all components participate at each monomial.
Position-over-term is mathematically valid if used consistently, but tends to
concentrate early pivots in one component and is unattractive for a six-way
cover.

The reference Singular semantics are:

```text
ring R=89,(q0,...,q36),(dp,C);
module N3 = /* the homogeneous cubic generators */;
degBound=5;
module G=std(N3);
```

For homogeneous input and global `dp`, `degBound=5` stops `std`/`slimgb` once
the degree exceeds five.  This is safe as a discovery truncation: every row it
does return is still in `N`.  It is not, by itself, a compact proof and the
10,767 dense polynomial-string input is not a recommended representation.

The repository weak-composition order also gives a useful negative preflight.
A generic 10,767-dimensional degree-3 image would occupy 1,794 complete
six-component monomial blocks plus three positions.  That prefix contains
the pure cubes only for `q16,...,q36`; it misses `q0,...,q15`.  Hence the
generic degree-3 pivot shadow is not irrelevant-primary.  Degree-4/5
prolongation or actual membership identities are needed.  This is an order
preflight, not a rank computation and not a proof that every degree-3 order
fails.

## Candidate discovery algorithms

### 1. Truncated module F4/F5: rigorous format, uncertain run

The best current design is a binary external-memory computation through
degree five under one fixed term-over-position order:

1. row-reduce the degree-3 cubic space and retain a derivation DAG to the
   original contractions;
2. generate degree-4 and degree-5 prolongations in signature order;
3. discard a prolongation only with a checked signature/involutive criterion,
   not merely because its leading monomial is already present;
4. stop as soon as the leading module contains a pure power for every one of
   the 222 pairs;
5. back-substitute only those selected rows and serialize their shared DAG.

This algorithm is exact and need not compute full degree-5 rank.  It becomes
low-memory if the signature criteria keep the pivot frontier small and the
shared DAG is sparse.  That favorable behavior has not been demonstrated.
Even at degree four the quotient dimension is at least

```text
548,340 - 398,379 = 149,961,
```

so there is no observed tiny Spencer quotient.  A raw F4 table may still
contain hundreds of thousands of degree-4 pivots and millions of degree-5
rows.  This is therefore an implementation proposal, not a feasibility
claim.

### 2. Direct degree-3 left syzygies: exact but infeasible unblocked

One can avoid materializing the 10,767 basis by solving directly for
`D(q) in S_3^690`:

```text
D(q) M2(q) = 0 in S_4^21,
D(q) M1(q) = q_i^5 e_j in S_5^6.
```

This is safe and slightly stronger than using only `K1*S_2`, because every
such `D` is a valid polynomial left syzygy.  Its dimensions are nevertheless

```text
unknown coefficients:       6,305,910
M2 constraint coordinates:  1,919,190
M1 output coordinates:      4,496,388
combined output:             6,415,578.
```

The sealed blocks have

```text
M1: 2,877,596 / 2,910,420 nonzero coefficients (98.8722%)
M2:    60,065 /   536,130 nonzero coefficients (11.2034%).
```

After monomial shifts, the direct operator has exactly
`26,847,283,879` structural nonzeros before elimination.  Values alone take
about 25.0 GiB at one byte each; sparse indices multiply that footprint.
This is not the desired low-memory route.

### 3. Dense lifts, black-box solvers, and involutive detours

A dense `K1*S_2` lift has 7,569,201 field coefficients.  Storing 222 of them
uses 1,680,362,622 bytes (1.56 GiB) before indices or metadata.  Direct `D`
lifts still use 1,399,912,020 bytes (1.30 GiB).  These sizes are acceptable
only if discovery yields sparse lifts or a strongly shared derivation DAG.

Block Wiedemann can lower resident memory, but with a block of 222 its Krylov
length is on the order of twenty thousand expensive tensor matvec steps, and
it does not automatically produce compact deterministic lifts.  It is not a
credible immediate run without an exact isotypic block decomposition.

Singular's `janet` interface accepts ideals, not modules.  Embedding `S^6` as
the part linear in six new tag variables and killing quadratic tag products is
exact, but adds variables and overhead to an already dense calculation.  No
module-native involutive or Spencer reduction with a proved smaller frontier
was found.  Likewise, selected `6 x 6` minors have degree 18; coordinate-wise
nonvanishing minors do not prove their common zero locus empty.

## Recommended next gate

Do not start a raw degree-5 CAS job.  First require one of:

- explicit representation/action matrices yielding independently verified
  invariant blocks of the degree-5 map; or
- a prototype binary signature-F4 pass through degree four whose measured
  pivot count, row density, and derivation-DAG size fit the intended memory
  cap.

Only then extend to degree five and stop on the 222-term cover.  Until such a
prototype succeeds, the compact certificate is mathematically valid but its
discovery is **not yet genuinely feasible** on the current evidence.  Nothing
in this report is a Stage-B or P25 verdict.
