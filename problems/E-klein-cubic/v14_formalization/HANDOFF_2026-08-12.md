# Faithful V14 no-map formalization: handoff

Date: 2026-08-12

Status: **OPEN / CONDITIONAL**

This document records the exact state of the scheme-level proof that there is
no equivariant rational map from the projectivization of a faithful
representation to the coordinate V14.  The normal-specialization architecture,

## Executive answer

The overall proof plan is now stable:

1. Specialize any equivariant rational map along the sigma-normal valuation.
2. Obtain a centralizer-equivariant rational map from the actual exceptional
   divisor `P(V+) x P(V-)` to the scheme-theoretic sigma fixed locus of V14.
3. Evaluate it at the generic point of the exceptional divisor.  Its function
   field is a pure transcendental extension of the V14 base field.
4. Extract normalized Plucker coordinates of the resulting fixed field point.
5. Use the kernel-checked sigma carrier certificate to put those coordinates
   in either the six-dimensional plus carrier or the four-dimensional minus
   carrier.
6. Prove that each branch descends projectively to a base-field V14 point:
   the minus branch through a nonsingular binary quadratic, and the plus branch
   through a determinantal plane cubic.
7. Convert that field-point descent into constancy of the original rational
   map.
8. Equivariance makes the constant value centralizer-fixed, contradicting the
   already checked D12 base-point exclusion.

The foundational definitions needed by this plan are present.  New definitions
are still needed for the concrete plus Segre/determinantal certificate and,
depending on the chosen proof organization, for scalar extension of
multivariate rational function fields.  The theorem inventory is not complete:
the two branch-descent theorems, the generic-point assembly, and the final
unconditional headline remain.

## Exact current endpoint

The faithful scheme-level reduction is
`SchemeGeometry.noEquivariantRationalMap_from_ambient_of_constancy` in
`V14Formalization/FaithfulHeadlineReduction.lean`.  In abbreviated form it says:

```lean
theorem noEquivariantRationalMap_from_ambient_of_constancy
    (R : FaithfulLinearRep k G V) (p q : Nat)
    (bp : Basis (Fin (p + 1)) k (R.plusEigenspace sigma))
    (bm : Basis (Fin (q + 1)) k (R.minusEigenspace sigma))
    (hconst : forall z : Scheme.RationalMap
        (exceptionalFor R p q bp bm).V.left v14FixedAction.V.left,
      z.IsOver (Spec k) -> RationalMapIsConstantOver z) :
    not HasEquivariantRationalMap
      (ambientFor R p q bp bm) V14SchemeModel.actionOver
```

This is the correct target shape.  It uses genuine `Scheme.RationalMap`, the
actual corrected normal valuation, the actual biprojective exceptional divisor,
and the actual coordinate V14.  It imposes **no dominance hypothesis**.  The
single remaining input is `hconst`.

The base field here is
`V14SchemeModel.k = GeometricV14Carrier.k = WeilRep.K`.  It is a cyclotomic
number field, not an algebraically closed field.  This matters in the plus
branch and is discussed below.

## Important pitfalls

1. **Do not add dominance.**  The headline concerns all equivariant rational
   maps.  `Scheme.RationalMap` is the correct object; dominance is needed only
   by particular function-field APIs and is automatic for action
   automorphisms where used.
2. **Do not use `PartialMap` as the headline object.**  It is an implementation
   layer beneath `Scheme.RationalMap`.
3. **Do not replace the exceptional divisor by `P^(p+q)`.**  It is
   `P(V+) x P(V-) = P^p x P^q`.
4. **Do not revive the wrong normal parameter.**  The correct chart is
   `(u,T,v)` with `T=minus_0/plus_0`.
5. **Respect contravariance.**  A scheme action induces pullback on function
   fields; do not force those maps into a covariant `MonoidHom` without an
   inverse/opposite convention.
6. **Sigma is not the identity on the source normal parameter.**  It sends
   `T` to `-T`; only the residual/exceptional action is identity.
7. **The plus normal form is Segre, not Veronese.**  Over `K(i)`, the relevant
   six-dimensional carrier is the cross term of two three-dimensional
   eigenspaces.  A `GL6` Veronese search adds an unjustified line-bundle choice.
8. **First-projection descent is not enough.**  Descend the second tensor-factor
   kernel line and reconstruct the original plus carrier vector.
9. **The base is not algebraically closed.**  Existing Weierstrass descent
   cannot be applied directly to `WeilRep.K`.
10. **Point-level results are sufficient but must be genuine.**  A global
    scheme decomposition of the fixed locus is unnecessary; descent of the
    generic field point plus the fixed-locus closed immersion is enough.
11. **Keep the two obstructions separate.**  The D12 certificate already rules
    out fixed base points.  It does not prove rational-map constancy.
12. **Track normalization.**  Some raw wedge coefficient packets elsewhere use
    `w wedge w = 2 * normalized Plucker`.  The current minus `Q` packet has
    already been checked against `D12Certificate.pluckerValue`; do not insert or
    remove a factor of two without a coefficientwise replay.
13. **Do not trust current README status.**  `README.md` and
    `FAITHFULNESS_CHECK.md` contain older operational/coset-era descriptions and
    need reconciliation only after the new unconditional theorem is proved.
14. **The worktree is shared and very dirty.**  Do not use `git add -A`, reset,
    or clean.  Stage only explicitly audited sources, generators, result
    packets, and this handoff.  Never commit `.lake/build` artifacts.
